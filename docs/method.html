The instrument · Evidence brought into light

How the monitor
defines its field of view

The program separates retrieval, selection, interpretation, and publication. It never fetches full text. Every interpretive statement is constrained to the available abstract.

01

Daily pipeline

One path from metadata to a readable study

GitHub Actions starts the monitor at 07:00 JST. A 07:20 fallback runs only when the first run did not complete successfully.

  1. Retrieve

    Request metadata and abstracts from Europe PMC, Crossref, and optionally arXiv.

  2. Normalize

    Convert source-specific records to a shared Paper structure.

  3. Unify

    Merge records connected by DOI, source identifier, or normalized title.

  4. Refresh

    Improve previously indexed records when a source later provides a longer abstract or richer metadata.

  5. Screen

    Require PopPK or pharmacometrics, AI or machine learning, and methodological evidence.

  6. Select

    Report new papers; otherwise choose one unreported, abstract-bearing paper published since 2020.

  7. Interpret

    Create four concise statements from the available abstract only.

  8. Publish

    Update Markdown, GitHub Issues, the canonical JSON catalog, and GitHub Pages.

02

Relevance score

A bounded measure of scope alignment

The score ranges from 0 to 100. It ranks eligible papers by explicit alignment with this monitor. It does not assess study quality, validity, novelty, risk of bias, or clinical usefulness.

PopPK evidence0–30

20 points in the title and 10 in the abstract.

AI evidence0–30

20 points in the title and 10 in the abstract.

Method evidence0–30

20 points in the title and 10 in the abstract.

Intersection0–10

10 points when PopPK and AI are both explicit in the title.

High70–100

A paper must pass the three-part eligibility gate before scoring. Repeated synonyms do not add points; each component records whether evidence is present in the title or abstract.

03

Evidence boundary

Interpretation stops at the abstract

Titles support discovery and scoring, but not the four interpretive statements. The program does not download PDFs, visit publisher full text, or inspect supplementary material.

01

Prior limitation

What gap or problem does the abstract identify?

02

Contribution

What method, framework, algorithm, or comparison does it describe?

03

New capability

What analysis or decision becomes possible according to the abstract?

04

Significance

Why might it matter for PopPK, pharmacometrics, or model-informed dosing?

With an OpenAI API key, the abstract may be paraphrased into these four fields. Without one, the fallback extracts supporting sentences directly. If the abstract does not support a field, the monitor states that it was not reported.

04

Source policy

Core indexes with an optional preprint supplement

Source Role Failure behavior
Europe PMC Biomedical metadata and available abstracts A failure is reported; the run can continue if another required source succeeds
Crossref Publisher-registered articles and posted content A failure is reported; the run can continue if another required source succeeds
arXiv Optional preprint supplement, queried at most once per JST day Rate-limit and timeout errors are logged internally but omitted from reports

05

Program structure

Small modules with explicit responsibilities

core.py

Data models, validation, normalization, de-duplication, scoring, JSON I/O, and HTTP requests.

sources.py

Clients for Europe PMC, Crossref, and arXiv.

insights.py

Abstract-only interpretation with optional AI paraphrasing and an extractive fallback.

literature_monitor.py

Retrieval orchestration, catalog refresh, selection, notifications, and state updates.

reporting.py

Canonical article records, Markdown reports, and GitHub Issues.

site_generator.py

Validates and transforms the catalog into data consumed by GitHub Pages.

data/articles.json

The canonical structured catalog used to build the site.

state/seen.json

Seen identifiers, source health, and run dates used to prevent duplicate alerts.

06

Known limits

A reading queue, not a systematic review

  • Keyword screening can produce false positives and false negatives.
  • Abstracts may omit important methods, validation details, and limitations.
  • The relevance score measures scope alignment, not study quality.
  • Source metadata may differ in dates, abstracts, and publication types.
  • API result limits and indexing delays prevent guaranteed completeness.
  • The archive fallback is a ranked convenience sample, not an exhaustive search.

07

Visual language

Chiaroscuro, geometry, and measured motion

The interface is an original digital design rather than a reproduction of an artwork. Selective light and warm earth colors organize attention, while the rotating geometric instrument represents repeated observation, comparison, and revision.

Light

Important information emerges from a restrained dark field.

Measure

Circles, axes, and score dials make the system’s boundaries visible.

Motion

Slow counter-rotation suggests iteration without competing with the content.

No museum image, painting file, or traced composition is embedded in the site. The interface uses original HTML, CSS, and SVG.
